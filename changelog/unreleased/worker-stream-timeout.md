### English

- Stop streaming chat from hanging on a stuck upstream. A Qoder stream request whose first byte never arrives (the symptom was `qwen3.8-flash` requests with only an entry log line and no `chat reasoning resolved`) now fails fast after a 30-second TTFB deadline, classifies as `first_byte_timeout` / `unavailable` with failover, and is retried on the next eligible account instead of hanging the client until it gives up. The deadline is on the response head only — once headers arrive, the SSE body streams under the request's normal lifetime, so long thinking-model output is not cut off.
- Give the worker daemon its own upstream timeout. The worker's `fetch` to the Qoder gateway previously had no `AbortSignal`, so a stalled upstream held the worker's in-flight slot forever. It now aborts on a 30-second first-byte deadline and a 300-second total-stream backstop, returning a stable `first_byte_timeout` / `stream_total_timeout` error so the Go side can classify and fail over. Both are tunable via `QODER_STREAM_TTFB_MS` / `QODER_STREAM_TOTAL_MS`.
- Add a worker liveness watchdog to the maintenance loop. Health probes previously ran only at boot plus on manual console refresh, so a worker that stayed "alive" as a process but stopped serving `/health` was never noticed and kept being routed to. Every 30-second tick now issues one lightweight `/health` round-trip per worker account; three consecutive failures (~90s grace, enough to ride out a transient blip or mid-rewarm) stop the worker and hand it to the existing `watchAccount` + `beginAccountRecovery` path, which reboots it with backoff. In-process accounts (WorkBuddy / Trae / Devin) are skipped and unaffected.

### 中文

- 流式 chat 不再因上游卡死而无响应地挂起。Qoder 流式请求如果首字节迟迟不到（现象是 `qwen3.8-flash` 请求只有入口日志、没有 `chat reasoning resolved` 出口日志），现在会在 30 秒 TTFB 阈值后快速失败，归类为 `first_byte_timeout` / `unavailable` 并触发 failover，切到下一个可用账号重试，而不是把客户端挂到自行超时。该超时只针对响应头：一旦头部到达，SSE body 回到请求原本的生命周期，长思考模型的输出不会被截断。
- 给 worker 守护进程加上自己的上游超时。worker 对 Qoder 网关的 `fetch` 此前没有 `AbortSignal`，上游停滞时会永久占用 worker 的并发槽。现在它在 30 秒首字节超时和 300 秒整体流式兜底任一触发时 abort，返回稳定的 `first_byte_timeout` / `stream_total_timeout` 错误，让 Go 侧分类并 failover。两者均可通过 `QODER_STREAM_TTFB_MS` / `QODER_STREAM_TOTAL_MS` 调整。
- 给维护循环加 worker liveness 看门狗。健康探针此前只在启动时和手动控制台刷新时跑，所以一个"进程还活着但 `/health` 不再响应"的 worker 永远不会被察觉，还会继续被路由命中。现在每 30 秒维护周期对每个 worker 账号发一次轻量 `/health` 探针；连续 3 次失败（约 90 秒容忍窗口，足以扛过瞬时抖动或 rewarm 中途）就停止该 worker，交给既有的 `watchAccount` + `beginAccountRecovery` 路径按退避重启。进程内账号（WorkBuddy / Trae / Devin）被跳过，不受影响。
