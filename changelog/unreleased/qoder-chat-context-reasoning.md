### English

- Fixed Qoder in-process chat requests losing the model's thinking/reasoning stream. `BuildPlainChatBody` now fills `chat_context` the way the reference Qoder client (and the working qoder2api) does: `chat_context.text`, `chat_context.extra.modelConfig` (`key` + `is_reasoning`) and `chat_context.extra.originalContent` carry the latest user prompt and the routed model identity. The gateway resolves the thinking channel from that block, so an empty `extra` made it answer with content only even though `model_config.is_reasoning` and `parameters.enable_thinking` were set. `source`/`version`/`session_type` were also aligned to the official client (`1` / `"3"` / `"qodercli"`). Reasoning now streams back as `reasoning_content` (and as Anthropic `thinking_delta` on `/v1/messages`).
- Fixed Qoder in-process catalog parsing and model discovery. `ModelInfos` previously expected legacy worker fields (`id`, `mapped_key`) and dropped every entry from raw gateway `/model/list` responses (which only supply `key` and `display_name`). Models are now derived from `key` and `display_name` via `CanonicalModelID`, restoring Qoder model routing (`qoder/qwen3.8-flash`, etc.) for in-process accounts. `catalog_source` now also merges in-process Qoder catalogs, and `manager_probe` triggers background model discovery for prober-less in-process accounts on startup.

### 中文

- 修复 Qoder 进程内 chat 请求丢失模型思考（reasoning）流的问题。`BuildPlainChatBody` 现在按官方 Qoder 客户端（以及可用的 qoder2api）的方式填充 `chat_context`：`chat_context.text`、`chat_context.extra.modelConfig`（`key` + `is_reasoning`）与 `chat_context.extra.originalContent` 带上最新用户输入和路由到的模型标识。网关依据该块决定是否走思考通道，之前 `extra` 为空导致即便设置了 `model_config.is_reasoning` 和 `parameters.enable_thinking`，上游也只回内容、不回思考。同时把 `source`/`version`/`session_type` 对齐官方客户端（`1` / `"3"` / `"qodercli"`）。现在思考过程会以 `reasoning_content` 流式返回（`/v1/messages` 入口则编码为 Anthropic `thinking_delta`）。
- 修复 Qoder 进程内模型目录解析与路由丢失问题。`ModelInfos` 之前仅兼容旧版 worker 的 `id` / `mapped_key` 字段，导致直连网关 `/model/list` 的原始数据（仅有 `key` 和 `display_name`）被当成空字段全部跳过，池中 Qoder 账号模型列表为空并报 `model_not_available`。现已自动兼容网关原生 `key` 与 `display_name` 派生 `CanonicalModelID`；`catalog_source` 也同步支持将无 worker 的进程内 Qoder 账号合并入展示目录，且 `manager_probe` 在探针刷新时对这类账号自动触发目录加载。
